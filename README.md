# System Architect Notes

Useful studying materials for System Architect and Software Engineers.

## 마이크로서비스 아키텍처 설계 가이드

### 1. 마이크로서비스의 핵심 원칙

- **단일 책임**: 각 서비스는 하나의 비즈니스 기능에 집중해야 합니다
- **독립적 배포**: 각 서비스는 다른 서비스에 영향을 주지 않고 개별적으로 배포 가능해야 합니다
- **분산 데이터 관리**: 각 서비스는 자체 데이터베이스를 가질 수 있습니다
- **장애 격리**: 한 서비스의 장애가 전체 시스템에 영향을 주지 않아야 합니다
- **기술 다양성**: 각 서비스에 가장 적합한 기술 스택을 선택할 수 있습니다

### 2. 도메인 분석 및 서비스 경계 설정

1. **도메인 주도 설계(DDD) 적용**
   - 핵심 도메인과 서브 도메인 식별
   - 바운디드 컨텍스트(bounded context) 정의
   - 유비쿼터스 언어(ubiquitous language) 확립

2. **서비스 경계 정의**
   - 비즈니스 기능을 기준으로 분할
   - 데이터 응집도는 높게, 서비스 간 결합도는 낮게
   - 너무 작거나 너무 큰 서비스를 피함
   - 팀 구조도 고려 (Conway's Law)

### 3. 통신 패턴 설계

1. **동기식 통신**
   - REST API
   - gRPC
   - GraphQL

2. **비동기식 통신**
   - 메시지 큐 (Kafka, RabbitMQ)
   - 이벤트 기반 아키텍처
   - 발행-구독(Pub-Sub) 패턴

3. **API 게이트웨이**
   - 클라이언트와 서비스 사이의 중개자
   - 라우팅, 인증, 로드 밸런싱, 캐싱

### 4. 데이터 관리 전략

1. **데이터베이스 선택**
   - 각 서비스에 적합한 DB 유형 선택 (SQL, NoSQL)
   - 데이터 일관성 vs 가용성 트레이드오프 고려

2. **데이터 일관성 패턴**
   - Saga 패턴
   - Event Sourcing
   - CQRS (Command Query Responsibility Segregation)

3. **데이터 중복 관리**
   - 필요 시 제한적 데이터 중복 허용
   - 데이터 동기화 메커니즘 구현

### 5. 인프라 설계

1. **컨테이너화**
   - Docker로 애플리케이션 패키징
   - Kubernetes로 오케스트레이션

2. **CI/CD 파이프라인**
   - 자동화된 테스트 및 배포
   - Blue-Green 배포, Canary 배포

3. **서비스 메시**
   - Istio, Linkerd 등 활용
   - 트래픽 제어, 보안, 모니터링

### 6. 모니터링 및 관찰성

1. **로깅**
   - 중앙화된 로그 집계
   - ELK Stack, Graylog 등

2. **메트릭**
   - 시스템 및 비즈니스 메트릭 수집
   - Prometheus, Grafana 등

3. **분산 추적**
   - 요청 흐름 추적
   - Jaeger, Zipkin 등

4. **알림 시스템**
   - 이상 징후 감지 및 알림
   - PagerDuty, OpsGenie 등

### 7. 보안 설계

1. **인증 및 권한 부여**
   - OAuth 2.0, JWT
   - 중앙화된 인증 서비스 (Keycloak, Auth0)

2. **서비스 간 보안**
   - mTLS
   - API 키, 토큰 관리

3. **보안 모니터링**
   - 침입 탐지 시스템
   - 취약점 스캐닝

### 8. 마이크로서비스 테스트 전략

1. **단위 테스트**
   - 개별 서비스 기능 테스트

2. **통합 테스트**
   - 서비스 간 통신 테스트
   - 소비자 주도 계약 테스트 (Consumer-Driven Contract Testing)

3. **엔드투엔드 테스트**
   - 전체 시스템 흐름 테스트
   - 성능 및 부하 테스트

### 9. 단계적 구현 전략

1. **스트랭글러 패턴(Strangler Pattern)**
   - 기존 모놀리스에서 점진적으로 마이크로서비스로 전환
   - 가장 가치가 높거나 격리가 쉬운 기능부터 시작

2. **반복적 개선**
   - MVP(Minimum Viable Product) 접근법
   - 지속적인 리팩토링 및 개선

### 10. 운영 및 거버넌스

1. **개발 표준 및 가이드라인**
   - 코딩 스타일, API 디자인 표준
   - 공통 라이브러리 관리

2. **문서화**
   - API 문서 (Swagger, OpenAPI)
   - 아키텍처 의사결정 기록 (ADR)

3. **성숙도 모델**
   - 마이크로서비스 성숙도 지표 설정
   - 지속적인 아키텍처 평가 및 개선
